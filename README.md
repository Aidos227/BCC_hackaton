# ReqAgent — агент проверки требований, который доказывает, а не рассуждает

Решение кейса «Агент проверки требований» (BCC-HUB × MNU FinTech Hackathon).
Агент принимает документ с требованиями (PDF, MD, TXT, DOCX), проводит статическое ревью
по ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и IEEE 830 (п. 4.3) и пишет отчёт на русском.

## Чем отличается от «одного промпта к LLM»

| Обычно | ReqAgent |
|---|---|
| Модель пишет замечания и сама указывает «где» | Каждая цитата **ищется кодом** в исходном файле. Страницу и строку проставляет код. Замечания без подлинной цитаты не попадают в отчёт, и это видно в приложении А |
| «Требование неоднозначно» | **Исполняемая модель требований.** Агент переводит правила документа в код, прогоняет через него критерии приёмки и граничные сценарии. Противоречие доказывается вычислением: «по правилу — январь, критерий ждёт февраль». Неоднозначность считается критичной, только если разные прочтения дают **разный наблюдаемый результат** |
| Модель решает, что критично | Критичность — это **решение, которое невозможно принять**. Код понижает «критично», если блокируемое решение не названо или противоречие подтверждено одной цитатой |
| Всё — дефекты | Продуктовые развилки отделены от дефектов: раздел «Вопросы владельцу продукта» |
| Свой формат отчёта | Агент **заполняет чек-лист «Ревью требований» из самого документа** (шаблон банка), ссылаясь на номера замечаний |
| Проверка один раз | `--compare` показывает, какие замечания закрылись после правки документа |

Конвейер (7 обращений к модели плюс код):

```
документ ─► чтение и индекс строк ─► 1 нарезка на атомарные требования (цитата + ID)
          ─► 2 проверка каждого требования (9 критериев 5.2.5)
          ─► 3 проверка набора (5.2.6 + трассируемость, версия, согласование)
          ─► 4 исполняемая модель: код правил + сценарии ─► песочница ─► находки
          ─► 5 детерминированные правила (заглушки, версия, пустые таблицы, расплывчатые слова)
          ─► привязка цитат кодом, отсев замечаний без подлинной цитаты
          ─► 6 скептическая перепроверка: подтвердить / отклонить / вопрос / дубль
          ─► 7 заполнение чек-листа банка ─► отчёт .md + .json + .model.py
```

## Установка и запуск (Windows PowerShell 5.1)

Нужен Python 3.9 или новее.

```powershell
git clone <ссылка на репозиторий> reqagent
cd reqagent
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
notepad .env        # впишите GEMINI_API_KEY=...
.\.venv\Scripts\python -m reqagent docs\requirements.pdf reports\report.md
```

Linux / macOS: те же команды, `python3` и `.venv/bin/python`.

### Как получить ключ LLM
1. Откройте https://aistudio.google.com/apikey и войдите в Google-аккаунт.
2. Нажмите «Create API key» и скопируйте ключ. Бесплатного тарифа достаточно.
3. Вставьте ключ в файл `.env` в корне проекта: `GEMINI_API_KEY=ваш_ключ`.

Модель по умолчанию — **`gemini-3.6-flash`** (`GEMINI_MODEL` в `.env`). Если она перегружена (503) или исчерпан бесплатный лимит (429), агент сам переходит на модели из `GEMINI_FALLBACK_MODELS`.
Поддерживаются также Claude (`ANTHROPIC_API_KEY`) и любой OpenAI-совместимый сервер, включая локальный
Ollama или LM Studio через `OPENAI_BASE_URL`. Так документ не покидает контур банка. Точная версия модели,
которую вернул API, пишется в паспорт отчёта.

### Команда и результат

```
python -m reqagent <путь к документу> <путь к отчёту.md> [--compare прошлый.json] [--no-model]
```

| Файл | Что в нём |
|---|---|
| `reports/report.md` | отчёт: паспорт, нарезка, проверка каждого требования, проверка набора, исполняемая модель, чек-лист банка, сводка, итог, вопросы владельцу, приложения |
| `reports/report.json` | все промежуточные данные: требования, кандидаты, вердикты перепроверки, прогоны модели |
| `reports/report.model.py` | исполняемая модель требований. `python reports\report.model.py` повторяет прогон сценариев без LLM |

Время прогона — 2–5 минут, 7–9 обращений к модели. На бесплатном тарифе при ответе 429 агент сам
ждёт и повторяет запрос.

## Как проверить, что агент не выдумывает

1. Откройте любое критичное замечание в `reports/report.md`. Рядом с каждой цитатой указаны страница и строка PDF.
2. Откройте `docs/requirements.pdf` на этой странице: цитата там есть дословно.
3. Для замечаний «найдено: исполняемая модель» запустите `python reports\report.model.py` и посмотрите, какой результат вычисляется и какой ожидает документ.
4. Приложение А отчёта показывает, что агент отбросил и почему.

## Независимая проверка качества

`eval/` — проверка, способная опровергнуть главное обещание агента.

- `eval/fixtures/autopay.md` — **незнакомый документ** с заложенными дефектами;
- `eval/fixtures/official_paraphrased.md` — **перефразировка** выданного документа: дефекты должны находиться снова;
- `eval/fixtures/official_fixed.md` — выданный документ, где **устранены три причины**: замечания по ним должны исчезнуть;
- `eval/keys/*.json` — разметка дефектов, `eval/score.py` — скорер **без LLM**, который сверяет цитаты;
- сравнение с **одним сильным запросом к той же модели** (`--baseline`).

```powershell
.\.venv\Scripts\python eval\run_eval.py --reps 2
```

Результаты лежат в [`eval/RESULTS.md`](eval/RESULTS.md).

## Тесты без LLM

```powershell
.\.venv\Scripts\python -m unittest discover -s tests
```

Тесты проверяют чтение PDF, привязку цитат, песочницу (запрет импортов, файлов и eval) и весь конвейер
на подставной модели.

## Безопасность
- Ключ хранится только в `.env`, который исключён через `.gitignore`. В репозитории лежит `.env.example` без ключа.
- Код модели требований, написанный LLM, перед запуском проходит проверку AST: разрешена только безопасная
  стандартная библиотека, запрещены файлы, сеть, `eval/exec` и dunder-атрибуты. Запуск идёт
  в отдельном процессе `python -I` с таймаутом.

## Ограничения
- Сканы PDF без текстового слоя не поддерживаются (нет OCR).
- Исполняемую модель строит LLM, поэтому она может ошибиться в реализации правила. Такие находки проходят
  скептическую перепроверку, а код модели лежит рядом с отчётом для ручной проверки.
- Разметка дефектов в `eval/` авторская, это не экспертная оценка банка.
