# Архитектура LSJ: Lint · Simulate · Justify

LSJ построен как **конвейер специализированных агентов с проверками кодом между ними**, а не как чат нескольких
моделей. У каждого LLM-агента одна узкая задача и своя JSON-схема ответа. Каждый переход между агентами охраняет
детерминированный код. Он не пропускает дальше то, что нельзя проверить: выдуманную цитату, сценарий без
фактов из исходной строки, критичное замечание без названного блокируемого решения.

```mermaid
flowchart TD
    IN[Документ PDF / DOCX / MD / TXT] --> G0{{Входной контроль · код}}
    G0 -- не прочитан --> DIAG[Отчёт-диагноз<br/>модель не вызывается]
    G0 -- годен / частично --> A1[1 · Нарезчик<br/>атомарные требования + цитаты]
    A1 --> C1{{Привязка цитат · код<br/>страница и строка}}
    C1 --> A2[2 · Ревьюер требований<br/>9 критериев ISO 29148 п. 5.2.5]
    C1 --> A3[3 · Аналитик набора<br/>п. 5.2.6, IEEE 830, A↔B]
    C1 --> A4[4 · Сценарист<br/>строки приёмки + граничные случаи]
    A4 --> C4{{Проверка фактов сценария · код<br/>даты, суммы, месяцы}}
    C4 --> A5[5 · «Слепой» трассировщик<br/>вывод только из правил]
    C4 --> A6[6 · Программист модели<br/>код без ожидаемых результатов]
    A6 --> SB{{Песочница · код<br/>AST-фильтр, python -I, таймаут}}
    A5 --> A7[7 · Сравнитель<br/>вывод правил ↔ критерий]
    SB --> M{{Слияние методов · код<br/>модель, опровергнутая трассировкой, отбрасывается}}
    A7 --> M
    IN --> R{{Правила · код<br/>заглушки, версия, внедрённые инструкции}}
    A2 & A3 & M & R --> GATE{{Шлюз доказательств · код<br/>нет подлинной цитаты → в приложение А}}
    GATE --> SK[8 · Скептик<br/>подтвердить / отклонить / вопрос / дубль]
    SK -- отклонил противоречие --> RT[Повторная слепая трассировка<br/>решает большинство 2 из 3]
    RT --> RULES
    SK --> RULES{{Правила критичности и склейка дублей · код}}
    RULES --> CH[9 · Заполнитель чек-листа банка]
    RULES --> IV[10 · Интервьюер<br/>уточняющие вопросы с вариантами]
    IV --> OWN[/Владелец отвечает<br/>--ask или файл ответов/]
    OWN -- --answers --> A1
    CH & IV --> REP{{Сборщик отчёта · код<br/>.md, .json, .model.py, .questions.json}}
```

## Роли

| # | Агент или шаг | Тип | Вход → выход | Что охраняет код |
|---|---|---|---|---|
| 0 | Входной контроль | код | файл → текст со страницами и строками, статус | сигнатура, кодировка, повреждённый или зашифрованный PDF, страницы без текста |
| 1 | Нарезчик | LLM | документ → атомарные требования с цитатами | цитата ищется в тексте, место вычисляет код |
| 2 | Ревьюер требований | LLM, пакетами | требования → оценка по 9 критериям, замечания | пакет, вернувший битый JSON, делится пополам |
| 3 | Аналитик набора | LLM | всё → противоречия, пропуски, трассируемость | для противоречия нужны две цитаты |
| 4 | Сценарист | LLM | правила и приёмка → сценарии | факты строки (даты, суммы, месяцы) обязаны попасть в сценарий |
| 5 | «Слепой» трассировщик | LLM | ситуация **без ожидаемого результата** → вывод по правилам | не видит критерий приёмки и не может под него подогнать |
| 6 | Программист модели | LLM | сценарии **без ожидаемых результатов** → код правил | AST-фильтр, отдельный процесс, таймаут, ремонт падений |
| 7 | Сравнитель | LLM | вывод правил и критерий → совпадает или нет | сравнивает только однотипные величины |
| 8 | Скептик | LLM | все кандидаты → вердикт | код понижает «критично» без блокируемого решения; закреплённые находки модели не отдаются; если скептик отклонил противоречие из трассировки, проводится повторная независимая трассировка, и решает большинство (2 из 3) |
| 9 | Заполнитель чек-листа | LLM | замечания → «Да/Нет» по шаблону банка | ссылки только на существующие замечания |
| 10 | Интервьюер | LLM | блокирующие замечания → не больше 10 вопросов с вариантами | вопрос без связи с подтверждённым замечанием не публикуется |
| — | Сборщик отчёта | код | всё → отчёт | текст отчёта пишет код, модель не пишет отчёт целиком |

## Почему так, а не «агенты в чате»
- **Проверяемость.** Каждое утверждение отчёта прослеживается до цитаты, вычисленного места или прогона кода.
- **Независимость методов.** Противоречие между правилом и критерием находят два способа, которые не видят
  ожидаемого ответа: трассировка и вычисление. Если они расходятся, побеждает трассировка, а находка модели уходит
  в приложение А.
- **Устойчивость к слабой модели.** Узкие задачи и починка JSON позволяют работать на бесплатном Gemini flash-lite.
  Ротация ключей и запасные модели переживают 429 и 503.
- **Замкнутый цикл уточнения.** Интервьюер задаёт вопросы, владелец отвечает, агент перепроверяет документ с учётом
  решений и показывает, какие блокеры сняты и что нужно внести в текст.
