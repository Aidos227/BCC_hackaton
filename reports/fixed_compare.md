## 7. Итог

**Итог: начинать разработку и тестирование по документу нельзя** — критичных дефектов: 3; каждый блокирует конкретное решение (см. раздел 7).

Что невозможно решить по документу сейчас:

- F-01: Какой HTTP-статус и формат ответа должен возвращаться при превышении верхней границы суммы порога (200 с ERROR или 400)?
- F-02: Какой тип данных (integer или string) должен иметь параметр amount в успешном ответе API?
- F-03: Как именно должны передаваться параметры метода — в теле POST-запроса (JSON) или через Query-параметры?

**Что исправить в первую очередь:**

1. **F-01** — Правила требуют разного: Превышение верхней границы порога. Принять решение владельцем: Какой HTTP-код возвращать при превышении лимита суммы — 200 с результатом ERROR или 400?
2. **F-02** — Противоречие типов параметров amount в запросе и ответе. Привести тип параметра amount в успешном ответе к integer или явно указать сериализацию в строку.
3. **F-03** — Противоречие способа передачи параметров и Content-Type. Перенести параметры запроса из Query в Request body для POST-метода или изменить REST type на GET.
4. **F-04** — Документ не определяет исход: Отправка запроса с неверным типом контента. Принять решение владельцем: В документации не указан конкретный HTTP статус-код и текст ошибки для случая передачи неверного типа контента (Content-Type: text/plain вместо application/json).
5. **F-05** — Отсутствие спецификации операции чтения порога. Добавить отдельное описание метода для чтения порога либо исключить упоминание чтения из описания метода сохранения.
6. **F-06** — Не указаны критерии успешности проверки пользовательской сессии. Уточнить: «1. Проверить валидность токена сессии пользователя в системе авторизации»
7. **F-07** — Не детализирован способ проверки принадлежности карты клиенту. Уточнить: «2. Проверить по базе данных АБС/процессинга, что переданный card_id принадлежит пользователю из сессии»
8. **F-08** — Не указаны HTTP-статусы успешного и неуспешного сохранения. Дополнить шаг указанием возвращаемых HTTP-кодов для успешного и неуспешного сохранения.
9. **F-09** — Неопределенность диапазона неуспешных кодов. Заменить фразу «и далее» на точное перечисление или диапазон (например, «400, 401, 403, 404, 500» или «все коды 4xx и 5xx»).
10. **F-10** — Возврат статуса 404 для чужой карты противоречит заголовку 403. Вынести описание статуса 404 в отдельный раздел или исправить код ответа в соответствии с заголовком.
