Требования: R-07, R-08; найдено: трассировка сценария
- Цитата (стр. 2, строка 13): «Покупка 31 января в 23:58 на 4 000 ₸ Провести 1 февраля в 00:03 по Алматы Февральский счётчик вырос на 4 000 ₸»

- Проблема: По правилам документа (вывод сделан без доступа к критерию): Покупка на сумму 4 000 ₸ увеличивает январский счетчик расходов (по дате совершения 31 января в Алматы), а не февральский. Расхождение: Сумма расходов в критерии ожидает увеличение февральского счётчика на 4 000 ₸, а по правилам покупка увеличивает январский счетчик расходов.

- F-02: Выбор HTTP-метода для API сохранения настроек

**Что исправить в первую очередь:**

1. **F-01** — Критерий приёмки противоречит правилам (S2). 
2. **F-02** — Противоречие типа HTTP-метода и назначения операции сохранения. Изменить REST type на POST или PUT для метода сохранения настроек.

4. **F-04** — Метод сохранения использует GET вместо PUT/POST. Изменить REST type на PUT или POST.
5. **F-05** — Не определены критерии и коды ошибок логики. Детализировать условия проверки суммы и переключателя, а также сопутствующие коды HTTP-ответов.
6. **F-06** — Противоречие между Content-Type и использованием query-параметров. Удалить требование к Content-Type: application/json для GET-запроса без тела.
7. **F-07** — Утверждение об успешности кодов 200 и 201 противоречит секции статусов. Исключить код 201 из списка успешных для данного GET-метода.
